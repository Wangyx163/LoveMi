# LoveMi AI 注册｜v1.9 原流程 + P1B v1.11（本地 / Vercel）

项目现包含独立的手机端前台。首页是 `index.html`，按参考图实现紫色渐变聊天、猫咪、人物卡、60% 阶段卡和 100% 完整画像卡。已有路由、模型理解与画像生成继续使用原引擎，调试工作台单独保留。

运行 `npm start`（Windows PowerShell 可用 `npm.cmd start`，或双击 `start_windows.bat`），打开 **http://127.0.0.1:8768/**；调试工作台打开 **http://127.0.0.1:8768/debug**。聊天会在本机浏览器保留，保存画像后也可再次查看。

仅检查界面时，可访问 `/?preview=chat`、`/?preview=cards`、`/?preview=60`、`/?preview=100`。这些地址展示固定的视觉样例，真实聊天请使用不带 preview 参数的首页。

**上传 GitHub 不会自动启动网站。** 仓库里的 `index.html` 是网页入口；真实模型聊天需要同时运行 Node 后端。GitHub Pages 只能展示静态页面与视觉样例，不能执行 `/api/model`。部署到支持 Node.js 的服务时，启动命令为 `npm start`，设置 `HOST=0.0.0.0`，端口可由平台的 `PORT` 环境变量指定。也可构建随包 Dockerfile：`docker build -t lovemi .`，再运行 `docker run --rm -p 8768:8768 lovemi`。

**Vercel 已有独立适配。** `vercel.json` 构建浏览器文件到 `public/`，`api/model.js` 与 `api/status.js` 自动部署为 Node Functions，复用本地网关。Vercel 不运行 `npm start`，也不需要常驻监听端口。之前直接上传静态页面时没有 `/api/model` 函数，因此能打开页面却无法调用模型。

猫咪素材与来源见 `assets/README.md`。

**本项目沿用你上传的 v1.9 参考实现流程。** 题目主线、进度权重、节点与模拟人物继续使用既有配置；原 85 项流程用例扩展为 121 项，另有 22 项路由与画像边界检查、11 项事实渲染与阶段洞察检查。增量变更如下：

- `P1B` 使用理解、承接与追问统一依据的新版，合并原有重复规则与示例；输入变量、输出字段和单次理解调用保持既有契约。
- `P3` 使用自然切入版重问引子，`P5` 生成有示例的 60% 核心洞察，`P6` 沿用 P5 洞察并生成伴侣期待和相处方式，`P7` 生成兴趣日常；`P1` 保留旧版用于 A/B 对照。
- `config.stage_rules` 的人物卡部分同步 v1.11 的追问边界；其他路由配置不做业务重构。
- HTML 与 `src/engine.js` 同步修复跳题对象判断、补充题状态、延后重问间隔及阶段入口；“真实模型”调用由本地 Node 服务代理，模拟回放和页面内状态/Prompt/测试面板保留。
- 新增独立模型配置 `config/models.json`，无需把 API Key 写入前端。

## 1. 本地运行（Node.js 18+）

**Windows：** 双击 `start_windows.bat`；或在项目目录终端执行：

```bash
node server.js
```

**macOS/Linux：** 执行 `./start_mac_linux.sh`（也可直接运行 `node server.js`）。

打开 **http://127.0.0.1:8768**。不要直接双击 HTML 文件，因为那样模型代理 `/api/model` 不可用。

页面有两个模式：

- **模拟回放：** 无需模型，直接选择场景，按“下一句”或“播放到底”。验证的是 v1.9 节点逻辑。
- **真实模型：** 自己在左下角输入「开始」，按实际流程回答。后端会按每个节点调用你配置的模型。页面右侧可查看节点轨迹、模型输出和状态。

### 部署到 Vercel

导入本仓库，Root Directory 选择包含 `package.json` 的项目根目录。Framework Preset 使用 **Other**，保留仓库 `vercel.json` 中的构建设置：Build Command 为 `node scripts/build-public.js`，Output Directory 为 `public`。已有项目更新后重新部署最新提交；若曾手动覆盖构建目录或框架，请恢复以上设置。

后端函数包含 `config/models.json` 和本次已授权随私有仓库提交的 `.env`，静态目录只复制指定前端文件，不包含密钥和后端源文件。Vercel 项目中的 `MODEL_API_KEY`、`MODEL_API_BASE` 环境变量优先于 `.env`，可以直接在项目 Settings → Environment Variables 中覆盖；修改后重新部署。保留 `fluid: true` 与函数 `maxDuration: 210`，给 P6/P7 的 180 秒网关超时留下返回响应的时间。

部署后先访问 `/api/status`，应返回 `ok: true`、`key_configured: true` 和六个节点模型名称；这里不会返回 Key。再回到不带 `preview` 参数的首页发送消息。界面预览页使用固定示例，不执行真实聊天。调试工作台仍可通过 `/debug/` 访问。

本地检查可运行 `npm run build` 和 `node tests/test_vercel.js`；它们验证静态构建、函数入口、Vercel 预解析请求体、环境覆盖与密钥隔离，不依赖线上部署，也不消耗模型额度。实际域名的网络、模型账户权限和 Vercel 部署日志需在对应项目中确认。

平台行为参考 [Vercel Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js)、[项目配置](https://vercel.com/docs/project-configuration/vercel-json) 与 [函数运行时长](https://vercel.com/docs/functions/limitations)。

## 2. 单独配置模型

模型配置均在 **`config/models.json`**，和提示词/流程代码分离。修改后下一轮调用即可生效。每个节点可以使用不同的 `model`、`temperature`、`max_tokens` 和 `timeout_ms`。

| 节点 | 思考模式 | 网关超时（可编辑） |
| --- | --- | --- |
| P1/P1B/P3/P5 | 关闭 | 60 s |
| P6/P7 | 开启 | 180 s |

当前服务已切回百炼 `https://dashscope.aliyuncs.com/compatible-mode/v1`，全部节点使用 `deepseek-v4.1-flash-1017`。网关发送 `enable_thinking=false/true`，P6/P7 的 `max_tokens=8192` 为思考与最终输出预留空间。按本次私有仓库部署要求，后端 `.env` 随项目提交；浏览器端无法读取密钥。

> 网页的“按生产超时执行”仍使用原流程的性能预算，云端调试请保持关闭。网关按上表超时控制实际请求。

接第三方兼容 OpenAI Chat Completions API 时：

1. 修改 `config/models.json` 中 `provider.api_base`，填到 `/v1`（或完整的 `/chat/completions`）。
2. 修改 `nodes.P1B.model` 等节点的具体模型名称。
3. 复制 `.env.example` 为 `.env`，在 `.env` 写 `MODEL_API_KEY=你的Key`；不要把 Key 写进 `models.json` 或网页中。
4. 重启服务；运行时 `MODEL_API_BASE` 环境变量也能临时覆盖 `provider.api_base`。

**注意**：本地模型网关使用的是 OpenAI-compatible `/chat/completions`，不是 Responses API；部分不支持 `temperature` 或 `max_tokens` 的模型，需要在配置中删除相应参数。模型不支持强制 JSON 结构时保持 `response_format_json=false`。浏览器不会收到密钥。

**编辑 Prompt 注意：**修改 `prompts/` 下对应源模板后运行 `npm run sync`，会将共享文本展开到 `data/prompts.json` 和调试页默认值；`npm run build` 也会自动同步。`npm test` 首先检查这些文件是否一致。五个系统源模板中的 `{{shared_behavior}}` 是构建占位符，复制到外部平台时应使用编译后的 `data/prompts.json`。P1 旧版和阶段规则仍单独维护。

网页“Prompt”面板中可直接修改并临时存入本机浏览器，下一轮生效，此类编辑**不会自动写回**源文件。网页里的“恢复默认”恢复当前节点的随包默认提示词。调试页按编译内容更新 `lm_shared_behavior_revision`：有新版时刷新 P1B/P3/P5/P6/P7 五个节点的旧缓存，之后保留本地编辑；阶段规则和 P1 不由此迁移。正式前台每次加载读取运行 JSON。

**2026-10-20 共享行为与输入精简：**五个模块共用最小人设及事实边界，各自的任务、输出接口与示例继续保留。事实文本补充 `field.sub` 和极性标记，保留原值、对象、硬性、条件和原话，避免同为“不介意”的烟酒要求失去具体含义；极性标记不会再次取反原有否定值。P1B 只删除与系统提示重复的说明，以及理解阶段不用的备用问句和场景列表，字段词典、当前实际问句、最近两轮问答和跨题提取继续传入。本轮未修改风险路由、追问额度或人物卡目标格式，也未增加模型调用。

**P5 与完整画像 core：**P5 按共享人设、角色目标、输入契约、理解与生成规则、输出及 Few-shot 组织，输出仍为 `{"attitude":"...","insufficient":false}`，20～35 字。不要求同时拼接情感与生活两面，优先提炼有事实支持的整体特点，依据不足时输出空文案与 `insufficient:true`。示例覆盖不同人物特点、信息边界和不足情况。100% 的 core 由 N32 直接复用 60% 卡片已经展示的原文，P6 无法覆盖；阶段卡使用兜底时也保持原文与兜底标记。旧会话没有阶段文案时，使用现有配置兜底，不补调 P5。正常继承不再误计为画像兜底。

60% 主文案不使用句号：P5 规则及示例同步调整，N25 在模型与兜底文案组装后统一移除句号，页面恢复旧阶段消息和视觉预览时也作相同处理。100% 继续沿用新阶段卡处理后的原文。

**P6 本次更新：**保留综合人物理解稿的 P60_N09～P60_N12 四组 Few-shot；`expect_ta` 描绘理想伴侣形象，建议 50～90 字，相处方式保留 100 字上限。用户模板用说明名称 `relation_facts/life_facts/core_60` 对接现有变量 `rel_facts/life_facts/p60_insight`。core 字段保留兼容接口，但只复制有效的 `core_60`；“无”“（暂无）”或空白时输出空字符串，不再根据新增事实修正或另行生成。最终 core 由上述 N32 规则确定。提示词源文件、运行 JSON、调试页默认值与内嵌引擎统一同步。

**P7 本次更新：**按本轮原文替换生活画像提示词，包含五组生活速写示例，去掉粘贴中的行尾反斜杠和 HTML 空格实体。输入仍为 `life_facts`，只输出 `{"daily":"..."}`，目标 40～110 字，依据不足时为空字符串。前台重新加载时读取最新提示词，调试页一次性刷新旧 P7 缓存，后续仍可在 Prompt 面板修改。

**开场与气泡分组：**在等待开场回应时，“好了”“ok”“可以的”等接受表达归为高接受意愿，使用 `intro_ack.accept` 中的“那就开始啦～想到什么都可以和我说，说得越具体，我就越懂你～”，整轮只出现一次。否定、暂缓、提问仍有各自承接；这个识别只用于开场。调试页通过 `lm_intro_ack_revision` 同步新接受承接。前台按内容组织气泡：普通承接、问题引子及对应问题在同一气泡，开场问候与准备引导分别显示；开始问卷时，接受承接一条，需求问题与其说明合为一条。已有消息按整条回复恢复，空行保留为气泡内段落。

**问题话术同步：**开场引导、提问/犹豫/其他类承接、10 道主问题与对应核心句已按用户 2026-10-19 提供的新表更新。主问题读取 script，重问读取 core，括号中的主题短语只作元数据；人物卡同步实际使用的多人、双人和单人问法。保留已确认的接受承接及其同义表达识别，需求题新首段中的“那就开始啦～”与接受承接去重，完整问题和说明仍合为一条消息。补充题沿用词库原表。`lm_question_bank_revision` 升级为 v4，同时刷新三类开场承接；路由、配额、最小信息条件和阶段规则不受此次文案同步影响。

**P3 与路由修正：**P3 已更新为自然切入、按需使用相关事实的新提示词，用户提示词变量保持原样。刷新时单独更新 P3 缓存，并为恋爱题的最小信息补上对象限制。引擎修复和当前实际跳题规则见 `docs/dialog-routing-current.md`，网页内嵌引擎与测试同步更新。

**P1B 理解、承接与追问：**按“理解本轮含义与范围 → 独立判断状态及提取事实 → 判断目标内值得了解的未知信息 → 表达承接和追问”整体改写。事实、承接与问句共用本轮含义，不新增理解对象或额外模型调用。区分人物指代、实际评价和明确伴侣要求；允许对已表达内容做轻微友好反应，不能联想出未说的理由、动机或性格。追问既要与本题相关，也要有信息收益，不能换词重复确认。完整 L1/L2/L3 定义集中到人物卡阶段规则，层级与是否值得继续提问分别判断；跨题兴趣、关系期待和明确 NEED 仍分别记录。调试页以 `2026-10-19-p1b-alignment-v16` 同步 P1B 和 CARD 阶段缓存。

**P1B 上下文与回复排版：**理解当前回复时传入本次会话最近两轮已完成问答，历史只帮助理解省略和指代，事实证据仍须来自本轮用户输入。普通对话的承接、重问引子和后续问题直接接成同一段，手机按屏幕宽度自然折行。调试页同步引擎、提示词和 P1B 缓存版本。

**ack 自然承接：**P1B 每轮输出一句 25 字以内的承接，按语境轻轻回应、顺着细节聊或照顾感受；系统用四组对照示例说明指代与评价、活动与目的、短答范围、场景与明确偏好的区别。普通问答与出卡共用承接校验，保留本轮合规 ack，缺失时用中性话术，不把模型不确定写成用户没想好。新输入清空上一轮临时理解结果，阶段按钮不重放旧承接；题序、追问次数与路由不变。

**分段与短否定：**配置主问题原有的段落保留在同一气泡，关系题第一段为承接加话题过渡，第二段为正式问题；动态追问的承接仍直接接问题。P1B 区分否定、拒答与否定范围不明；经历问句答“没”可有效回答且没有新增事实，不能推断消费性格。并列问题中未确定的字段留空，沿用已有延后重问，不新增澄清分支或额度。

**人物卡与 P3：**L1 引导其他方面，L2 开放了解具体表现或相处场景，只有明确择偶要求才写 NEED、按 L3 停止；场景本身不自动升级。P3 仅在延后重问时生成引子，不判断回答或生成普通追问，不评价上一轮选择；核心问题仍由代码原样提供。

人物反馈沿用话术表中的 L1/L2/L3 定义，阶段规则集中维护在 `prompts/P1B_stage_rules.json` 并同步到运行配置；边界示例集中在 P1B 系统提示词。实际追问使用当前人物名字，仍遵守现有停止条件及系统额度。
