# 当前对话顺序与跳题逻辑

本说明对照当前运行的 `src/engine.js` 和网页内嵌引擎，记录 2026-10-17 修正后的实际行为。

## 主线

开场问候 → 用户回应 → 理想型需求 → 推荐人物卡 → 人物反馈 → 生活中的你 → 恋爱里的你 → 60% 卡。

选择继续后：宠物 → 烟酒 → 消费观 → 事业与关系 → 感情经历 → 开放补充 → 完整画像。

人物反馈中间可以有最多两次追问。普通题的追问、延后重问和阶段补充题会插入主线，因此实际聊天不一定逐题等距推进。作息不单独提问，仅在用户顺带提到时记录。

## 跳题依据

下一道主问题已有最小信息，或用户已拒答该题，就跳过并结算进度。

| 主问题 | 最小信息条件 |
| --- | --- |
| 理想型需求 | 任意一条有效择偶要求 |
| 人物第一感觉 | 人物好感选择或都没感觉等有效反馈 |
| 生活中的你 | 自己的兴趣活动 `Q1.items` |
| 恋爱里的你 | 双方关系期待 `Q8.expectation`，或自己的关系推进节奏 `Q4.pace`，任一即可 |
| 宠物 | 是否养宠物或是否喜欢小动物，任一即可 |
| 烟酒 | 自己的吸烟和饮酒两项必须齐全 |
| 消费观 | 消费倾向或决策条件，任一即可 |
| 事业与关系 | 倾向或协调方法，任一即可 |
| 感情经历 | 愿意与 TA 交流到什么程度 |
| 开放补充 | 最后一轮直接收原话并生成画像，不调用回答理解模型 |

这些是配置中的最小门槛。例如恋爱题已有自己的慢热节奏，即可跳题，并不要求同时回答完整的相处期待。此前在开场需求轮顺带说出的自己的信息只记录，不用于覆盖后续主问题。

有矛盾附注的字段暂不再追问，也不生成事实标签；判断最小信息时仍按该对象的信息已被触及处理。它不代表已有确定结论。

## 追问、重问与补充

- 追问紧跟当前题：已有最小信息、模型判断值得补充、未拒答且额度足够，普通题最多一次。理想型需求、补充题不追问；人物反馈使用独立的最多两次判断，并受阶段共同额度限制。
- 延后重问用于尚未取得最小信息、未拒答、回答状态为说不清/答了一部分/跑题的题目。先发一道其他题，答完后再回到原目标；每题最多一次。理想型需求和补充题不登记这类延后重问。
- 补充题也算一道实际发出的其他题，可以满足上述间隔。回答后先执行已到期重问，再继续主线。
- 路由优先级为当前题的即时追问 → 已到期重问 → 下一道主问题；到达配置的补充节点时，可先插一道补充题。
- 前半额外额度为 3 次，后半为 2 次，追问、延后重问、补充题共同消耗，阶段之间不结转。
- 补充条件为本阶段累计处理的回答次数少于 5、尚有额度且本阶段没用过补充题。追问的回答也计次数；无效、拒答也可能计次数，因此这不是“保证获得五个有效回答”。每阶段最多补一道。前半在出卡前判断，后半在开放补充前判断。
- 同一题首次反问会用固定说明加核心句原样重发，第二次反问跳过。此规则目前也适用于需求题；它与“延后重问”不同。
- 理解模型主备都失败时，第一次保留原题请用户重说，同一题再次失败按说不清推进。

## 60% 与 100% 的入口

60% 卡后，只有明确的画像操作才提前生成完整画像。目前识别配置的生成按钮原文以及“生成画像”“直接完成”“完成”这些完整消息；其他文字进入后半阶段。“我还没完成”“我不想生成画像”等句子不会提前生成。

后半主问题若已在前半全部获得有效信息，仍在开放补充前检查一次补充题条件。开放补充回答后立即生成画像，不再回头追问。

## 本次修复

1. 最小信息按对象校验，避免把“希望 TA 慢热”当成用户自己的恋爱状态。
2. 初始化补充题状态，兼容旧会话，拒答补充题不再因缺少状态而崩溃。
3. 补充题计入延后重问间隔，避免末题未答出却直接结束阶段。
4. 60% 入口使用明确操作匹配，避免文字中出现“完成”就提前生成。
5. 后半前置问题全被覆盖时，仍检查开放补充前的补充题。
6. P3 校验按 4～22 字、单句和指定句尾执行；引子主备都不合格时仅发核心句。
7. 测试捕获流程异常时明确判为失败，避免空断言列表被当作通过。
