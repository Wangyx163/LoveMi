最终流程（v1.8）

#环节做什么进度
1开场两段问候，以“准备好了吗～？”结尾；用户回任意一句后，按提问 / 犹豫 / 其他三类承接一句，再发需求题（三段脚本原文）0%
2开场需求用户讲想找的人；对 TA 的要求记为需求（硬性 / 偏好）；不追问、不重问+10%
3推荐出卡有有效需求 → 需求匹配；没有 → 主页匹配；固定规则 → 硬筛 → 放宽 → 排序 → 差异 → 展示—
4人物反馈 + 追问按 L1 / 笼统 L2 / 具体 L2 / L3 决定是否追问，最多 2 次+30%（三个节点）
5生活中的你脚本原文；最多追问 1 次+10%
6恋爱里的你脚本原文（含过渡句）；最多追问 1 次+10%
7补充问题（条件）本阶段答题少于 5 题、额度还有 → 插 1 道；不涨进度—
860% 标签卡阶段消息 → 主文案（20～35 字）+ 3～4 个标签 → 两个按钮= 60%
9后 40%宠物 → 烟酒 → 消费观 → 事业与关系 → 感情经历；每题最多追问 1 次5/5/10/10/5
10补充问题（条件）同第 7 步，在开放补充前判断—
11开放补充只采集原话，不调理解模型+5%
12100% 画像阶段消息 → 核心洞察 / 我对 TA 的期待 / 兴趣日常（含标签）/ 我的相处方式 → 保存画像 / 回到首页= 100%

每一轮的固定节奏

用户随时可以退出（只保留对话）或重新开始（回到开场）。正常一轮只调 1 次模型（⑤ 回答理解，承接也在这次里给出），主问题直接发脚本原文。只有“换场景重问”那一轮多调一次 P3 写引子；60% 和 100% 各调一次画像模型。模拟时延：普通一轮约 2 秒，画像（限预算深度思考）约 13～18 秒。

阶段进度单元与权重说明

额外提问额度与节奏下限

阶段额度 B = ⌊N × r⌋节奏下限
前 60%N = 4，r = 75% → 3 道答题少于 5 题 → 出 60% 卡前插 1 道补充问题
后 40%N = 6，r = 35% → 2 道答题少于 5 题 → 开放补充前插 1 道补充问题

额度由追问、换场景重问、补充问题共用；替换优先于补充；拒答的题不再追问、不再重问；阶段结束不结转。

追问

用户说人物卡怎么做
只说喜欢谁（L1）追问一次：哪里吸引你
理由笼统（好看、顺眼、名字、玩笑）追问一次，问具体是哪一点；多选时针对理由笼统的那一位
理由具体（具体 L2）额度够时可再追问一次（往“对另一半的要求”引），必须换角度
说出对另一半的要求（L3）不追问，记为需求（代码兜底）
追问后说不清 / 拒答 / 跑题停，进入下一题（代码兜底）
追问②和追问①几乎一样拦下不发（代码兜底，文字重合 ≥70%）

其他题：每题最多追问 1 次；开场需求、补充问题不追问。

特殊回答

情况谁判断怎么做
空 / 纯标点 / 重复字 / 长串数字 / 键盘乱码代码（类别规则）不调模型，按“说不清”；开场需求题还包括纯表情 → 主页匹配
说不清（敷衍）模型兜底氛围承接（6 条轮换）+ 下一题；之后额度够时隔一题换场景重问（模型只写引子，核心句不变）
反问模型“我想了解你的{主题}呀~” + 核心句；同一题第二次 → 跳过
拒答模型不写事实；这题以后不追问、不重问
安全风险模型（只给定义）口头关怀一句 + 照常下一题；本题跳过；关怀后不接欢快过渡句
前后矛盾模型不选边，记矛盾附注；不重问、不出标签；画像阶段综合
改口模型旧值失效，新值生效，标签重算
注入 / 让你改规则模型不执行；输入加定界符，输出由代码校验，流程由代码决定
模型失败代码主模型失败 → 备用模型；都失败 → 原题保留一次，再失败按说不清推进；问句失败 → 核心句；画像失败 → 事实模板

合规与输入

屏蔽词库分三类：合规（事实不入库，问句 / 承接 / 画像出现即不合格）、产品不问（身高、体重）、画像诊断词。联系方式不入库。送模型的输入截断：开场需求 600 字、开放补充 500 字、其他 300 字。超时：理解 4 秒、引子 3 秒、60% 文案 8 秒、关系画像 20 秒、生活画像 15 秒。

一条事实

{field, sub, subject, value, strength?, polarity?, condition?, evidence, status:"已确认", active, turn, ver, src}。subject 取 自己 / TA / 关系 / 候选反馈；strength 只用于需求（硬性 / 偏好）；src 记录来自哪道题（开场需求里说的“自己”的信息不算覆盖）。

一张推荐卡

{key, id, name, age, city, school, tags[], tag_ids[], rows[][], score, source:"need|home", filter_hit:{count, items[]}}。filter_hit 给前端显示“满足 x 个筛选条件”。
